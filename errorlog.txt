LAWYER SELECT - ERROR LOG
Checked 20 October 2026: read every source file, ran the TypeScript check and the production build (both pass), and drove every screen in a real browser at desktop and phone sizes, with the AI service both working and switched off. Live database writes were blocked during testing, so no real data was changed.
One error per line, most serious first. "(tested)" means the error was reproduced in the browser or by running the code directly; the rest were found by reading the code.
Total: 105 errors - 10 critical, 24 high, 47 medium, 24 low.
Re-checked 20 October 2026 (evening) after the first round of fixes: items marked "(re-opened)" were removed from this log but are not actually fixed yet; items marked "(new)" were introduced by those changes.

[CRITICAL] Payments: Opening the site with "?payment_success=true&case_id=..." in the address unlocks that lead for free - the return-from-Stripe code unlocks the case even when the payment check fails or no receipt is given. (re-opened)
[CRITICAL] Payments: The payment-check route (verify-session) answers "verified" for any receipt number whenever the Stripe key isn't configured on the server. (new)
[CRITICAL] Accounts: There is still no real login - "signing in" only saves a name in the browser, anyone can "join" as a lawyer with no password, the "Quick Demo" buttons sign you in as listed lawyers such as Elena Vance with no password, and a failed Google popup silently signs you in as a made-up "Google Verified Client". (re-opened)
[CRITICAL] Privacy: The "locked" client details for the sample cases are still built into the public page files and every dossier is kept in the browser's own storage, so anyone can read them with developer tools - the lock only hides them on screen. (re-opened)
[CRITICAL] Core function: A lawyer who pays on their own device never receives the client's details, because the confidential details only ever exist in the browser of the client who posted the case. (re-opened)
[CRITICAL] Privacy: The app downloads entire database collections - every chat, purchase and profile, not just the visitor's own - into each browser, so if the database is open every visitor receives everyone's private conversations. (new)
[CRITICAL] Chat: Messages still can't reliably reach the other person - the only real Firebase session is anonymous and its ID never matches the chat's client or lawyer, so the new rules would reject every chat save (and without the rules, every chat is public). (re-opened)
[CRITICAL] Database security: The new rules let any signed-in user mark any lead as claimed by themselves, and create purchase records, without paying. (new)
[CRITICAL] Database security: The new rules grant access by the email address in the login, which Firebase doesn't verify for email sign-ups, so someone who registers with a client's email could read that client's chats or change a lawyer's profile. (new)
[CRITICAL] Firebase safety: firestore.rules replaces the rules for the whole database, so deploying it to the shared "ai-foundation-firebase" project would cut off every other app that uses that database. (new)
[HIGH] Security: The Gemini key and Stripe secret key that used to be written in the code are still in the project's git history and must be replaced with new keys; the old Stripe key is also passed on the command line of the Stripe tool running in the background. (re-opened)
[HIGH] Database security: The new rules let anyone create a lawyer profile under any ID and mark it "verified" themselves. (new)
[HIGH] Payments: The Stripe payment-confirmation handler (webhook) only writes a log line - it never records the purchase or unlocks the lead.
[HIGH] Payments: The payment-confirmation handler trusts any message that simply leaves out the Stripe signature (or arrives while the webhook secret isn't set), so anyone can fake a "payment completed" message; the webhook secret is also missing from the local settings file.
[HIGH] Payments: A purchase record marked "completed", with a made-up Stripe receipt number, is saved even when no payment happened. (tested)
[HIGH] Payments: Leads are sold as "exclusive", but nothing stops the same lead being sold to several lawyers - the checkout route doesn't check who is calling, whether the case exists or whether it is still open, and there is no single-buyer lock.
